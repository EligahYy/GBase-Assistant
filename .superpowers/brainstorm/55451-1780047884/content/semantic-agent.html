Semantic Mapper Agent 工作流程

ReAct 循环：理解用户意图 → 探索 Schema → 输出精确映射
用户: "查询最近一个月各产品线的销售额，用柱状图展示"

Semantic Mapper Agent (ReAct 循环):

Step 1: Thought: 用户想查销售额，需要找到销售相关表和金额列
        Act: search_schema_semantic("销售额 产品线 月份")
        Observe: 返回 top-10 相关表: [product_sale(0.92), product(0.88),
                sale_order(0.85), customer(0.72)...]

Step 2: Thought: product_sale 最相关，需要看它的列结构和 COMMENT
        Act: get_table_profile("product_sale")
        Observe: DDL + 列信息:
          - id INT PRIMARY_KEY "主键"
          - product_id INT FOREIGN_KEY→product.id "产品ID"
          - pay_amount DECIMAL(12,2) MEASURE "实际支付金额(元)"
          - created_at DATETIME TIME_DIMENSION "订单创建时间"
          - status TINYINT ENUM{0:待支付,1:已支付,2:已退款} "订单状态"

Step 3: Thought: pay_amount 是"销售额"对应的列，product 表需要 JOIN
          获取产品线名称。需要确认 JOIN 路径。
        Act: find_join_path("product_sale", "product")
        Observe: product_sale.product_id = product.id

Step 4: Thought: 语义映射完成。"产品线"对应 product.name 或 product.category，
          需要查看 product 表确认。
        Act: get_table_profile("product")
        Observe: product.category VARCHAR "产品线" ← COMMENT 精确命中！

Step 5: Final Output:
        {
          "tables": ["product_sale", "product"],
          "columns": {
            "product_sale": ["pay_amount", "created_at"],
            "product": ["category", "name"]
          },
          "business_terms": {
            "销售额": "product_sale.pay_amount",
            "产品线": "product.category",
            "最近一个月": "product_sale.created_at >= DATE_SUB(CURDATE(), INTERVAL 1 MONTH)"
          },
          "join_paths": ["product_sale.product_id = product.id"],
          "chart_hint": "柱状图, X=产品线, Y=销售额",
          "confidence": 0.92
        }

与原方案 B 的对比

维度方案 B (静态 YAML)方案 B+ (Agent)
维护成本需人工维护自动理解，YAML 仅作补充
新术语覆盖未录入则命中不了LLM 推理理解
与现有架构融合独立模块，需改造 Grounding作为 LangGraph 节点/Agent
LLM 调用成本无额外 LLM 调用多 1-3 次 LLM 调用
延迟毫秒级增加 2-5 秒
精确度取决于配置质量LLM 推理 + 工具验证
